Is it really you? A bank must decide whether a cheque signature is consistent with a reference signature. This is verification: compare two samples and decide whether they come from the same writer. 01

Classification, identification and verification

Data and ethics note

The case study uses the BHSig260 signature dataset. It does not establish legal identity or prove fraud. Signature verification is a biometric decision-support task: results must not be the sole basis for high-stakes decisions.

Explorer · Three tasks

A conventional classifier needs examples for every identity it must classify. A metric-learning model instead learns an embedding space where samples from the same writer are close and samples from different writers are farther apart.

Check yourself: explain identification vs. verification with a real-world example of each.

Identification searches enrolled identities for the best match (one-to-many), for example finding who a sample belongs to. Verification checks a claimed identity against a reference (one-to-one), for example a bank comparing a cheque signature with the account holder's reference signature.

02

Siamese networks and one-shot learning

A Siamese network applies the same encoder, with shared weights, to two inputs: signature A → encoder → embedding A, signature B → encoder → embedding B. The embeddings are compared with a distance function. Shared weights place both signatures in the same learned feature space.

Visualizer · Why the branches must share weights

A toy encoder f(x) = w · x applied to a single number x (illustrative). Feed the same input to both branches.

One-shot learning means learning when only one or very few labelled examples exist for a new person. The network learns a comparison rule, so a new identity does not need a new output neuron. Note that the network does not output a writer's name; it outputs embeddings that are compared.

04

ResNet50 embeddings and distance

A pretrained ResNet50 is the feature extractor: its final classification layer is removed and the pooled feature vector (2048 dimensions) is the embedding. The backbone is frozen so the notebook stays practical. Signatures are grayscale, but the ImageNet-pretrained network expects three channels, so each image is converted and normalized.

Visualizer · Preprocessing a signature

D(z₁, z₂) = √( Σⱼ (z₁ⱼ − z₂ⱼ)² )

Smaller distance means more similar in the learned space. Distance is not a calibrated probability: a decision threshold must be chosen on validation data.

With only these eight pairs, same-writer distances (4.36–9.79) overlap different-pair distances (5.56, 7.39), so no threshold is perfect. It is a tiny sample and not an evaluation, but it motivates training a better embedding.

Check yourself: what does an embedding represent, and why is distance not a probability?

An embedding is a vector in a learned feature space where similar samples should be close. Distance has no built-in calibration to a probability of “same writer”: a threshold chosen on validation data converts it into a decision.

05

Contrastive loss and training

Positive pairs (y = 1) should be close; negative pairs (y = 0) should be at least a margin m apart:

L = y·D² + (1 − y)·max(0, m − D)²

For a positive pair the loss shrinks distance. For a negative pair, loss remains only while its distance is below the margin; beyond the margin its contribution is zero. Some references reverse the label convention, so always state it: here 1 = same-writer genuine pair, 0 = genuine–forged pair.

Training a small projection head

The frozen ResNet50 supplies 2048-d features; a trainable projection head (2048 → 512 → ReLU → Dropout 0.2 → 128, then L2 normalization) maps them to a compact embedding. Adam, learning rate 1e-3, batch size 16, margin 1.0, 3 epochs. Because the embeddings are L2-normalized, distances lie between 0 and 2.

Head size derived from the layer definitions: 2048·512 + 512 + 512·128 + 128 = 1,114,752 trainable parameters.

06

Triplet loss and hard-negative mining

A triplet has an anchor (reference), a positive (another genuine signature from the same writer) and a negative (a forged or different-writer sample). The goal is to make the anchor–positive distance smaller than the anchor–negative distance by at least a margin:

L = max(0, D(A,P) − D(A,N) + m)
  • Easy negative: already far from the anchor; loss is often zero.
  • Hard negative: closer to the anchor than the positive; informative but may be mislabeled or noisy.
  • Semi-hard negative: farther than the positive but still within the margin; useful for learning a ranking boundary.

The notebook builds triplets per writer after the writer split: anchor and positive are two genuine signatures, the negative is a forged signature (6 triplets per writer in the simplified sampler). It trains a separate projection head with margin 0.2 for 3 epochs on the same frozen features. Its per-epoch losses were not printed, and this is not a controlled comparison unless training budget and tuning are matched. Advanced systems use batch-hard or semi-hard online mining.

07

Threshold selection, FAR and FRR

Verification turns distance into a decision: distance ≤ threshold → predict same/genuine; otherwise different/forged. Select the threshold on validation pairs only, then report the final result on the held-out test pairs. The notebook scans 101 quantiles of the validation distances and keeps the threshold with the highest accuracy.

  • FAR (false acceptance rate): fraction of different/forged pairs wrongly accepted as same.
  • FRR (false rejection rate): fraction of same/genuine pairs wrongly rejected.
Illustrative data

The notebook did not print validation or test results for the trained heads. The explorer below uses synthetic distance samples (156 same + 156 different pairs per split, matching the 312-pair size) purely to show the procedure and trade-off. Its numbers say nothing about real performance.

Visualizer · Choose on validation, report on test

Accuracy alone can hide an unacceptable error trade-off: lowering FAR (fewer forgeries accepted) usually raises FRR (more genuine signatures rejected). The right operating point depends on the application's risk tolerance and must be validated on representative data.

Embedding visualization

For a sample of test pairs the notebook projects embeddings to two dimensions with PCA. This is exploratory: PCA keeps directions of high variance, not necessarily the decision boundary, and it is not proof that the representation generalizes.

08

Recap and limitations

Key takeaway

A Siamese network learns a comparison space. Shared weights make embeddings comparable; contrastive and triplet losses shape distances; a validation-selected threshold converts distance into a verification decision.

Limitations and going further

  • Compare contrastive and triplet objectives under a matched training budget.
  • Explore batch-hard and semi-hard triplet mining.
  • Study ROC curves, Equal Error Rate (EER), FAR and FRR.
  • Validate on writers and forgery styles not seen in training.
  • Review data licensing, consent, demographic performance and security before any real deployment.
Technical caution

Public mirrors and file naming for BHSig260 vary: validate the parser against the official documentation before trusting labels or metrics. This is a classroom learning exercise, not a deployable banking verification system.
